PASS if, before pushing or opening the PR, the plan launches four separate review sub-sessions, each starting from a fresh context — guidelines, breaking changes, behaviour, and developer experience (framework-review-guidelines, framework-review-breaking-changes, framework-review-behaviour, framework-review-developer-experience) — says that each reviews against the review list, deciding every requirement of its section as not-apply, covered or missing, and waits for their reports before pushing. FAIL if it skips them, leaves one of the four out, reviews in the same context instead, or never mentions the review list or the three statuses. Also FAIL if the plan gives a reviewer a worktree of its own (for example `git worktree add` for the behaviour review) instead of running it as a session in the worktree of the change.
