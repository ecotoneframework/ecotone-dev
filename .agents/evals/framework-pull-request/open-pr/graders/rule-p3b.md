PASS if the plan says the four review sub-sessions run as Orca sessions (Orca workers started in the current workspace or worktree, for example through the orchestration skill or `orca orchestration worker-start --worktree current`) when the session runs inside Orca, and as subagents only when Orca is not available. A plan that cannot tell whether Orca is available passes when it states this order of preference, or says it will check for Orca first and use subagents only if it is absent. FAIL if the plan runs the reviews as subagents (or through a Task or Agent tool) without first preferring Orca sessions, treats the two as an equal choice, or never says how the review sub-sessions are run. Also FAIL if the plan gives an Orca review worker a new worktree of its own instead of the current one. Also FAIL if the plan names a model for the review sessions other than Claude Opus 5.5 (`claude-opus-5-5`, "Opus"), or says the reviews run on the implementing session's own model. A plan that never mentions the reviewers' model fails too: it must say the review sessions run on Opus 5.5.
