PASS if, before `git push`, the plan itself runs four separate review sub-sessions of the merged diff — guidelines, breaking changes, behaviour, and developer experience (framework-review-guidelines, framework-review-breaking-changes, framework-review-behaviour, framework-review-developer-experience) — either resuming the sub-sessions that reviewed the pull request earlier or starting new ones from a fresh context, without asking the user whether to run them, and waits for their reports before pushing, although the PR is already open and the user is in a hurry. FAIL if it pushes first, skips or shortens the reviews because of the hurry or the open PR, asks whether to run them, leaves one of the four out, or reviews the change itself in the implementing conversation instead. Also FAIL if the plan gives a reviewer a worktree of its own (for example `git worktree add` for the behaviour review) instead of running it as a session in the worktree of the change.
