PASS if the report gives each behaviour requirement of the review list (the BH ids) a line with one of the three statuses not-apply, covered or missing (any clear spelling counts, such as 'not applicable' or 'does not apply'), including the ones that are covered or do not apply (requirements that do not apply for one shared reason may be grouped on one line, and a line that refers to another line for its details, such as 'see BH5', carries that line's details), each missing one carrying a location, a concrete failing scenario and the test to add or the fix, and states a NOT PASSED result naming the missing requirements. A file name, class or test name counts as a location: the change under review is given as a summary without line numbers. A missing requirement whose gap is a test or a path that does not exist yet has no code to point at: for it the scenario and the test to add are the location, and it passes without a file name. FAIL if requirements are left undecided (only the problems are listed), if missing ones lack a failing scenario or a test or fix, or if there is no explicit PASSED / NOT PASSED result. The reviewer cannot open the repository or search it in this case: a report that says so, or that calls some decisions provisional for that reason, is judged on its content exactly as any other and still passes. Each missing one must also name the skill to load to cover it (for example 'skill: framework-testing'); FAIL if the missing requirements name no skill.
