PASS if the report gives each breaking-changes requirement of the review list (the BC ids) a line with one of the three statuses not-apply, covered or missing (any clear spelling counts, such as 'not applicable' or 'does not apply'), including the ones that are covered or do not apply (requirements that do not apply for one shared reason may be grouped on one line, and a line that refers to another line for its details, such as 'see BH5', carries that line's details), each missing one naming what breaks and the fix, and states a NOT PASSED result naming the missing requirements. FAIL if requirements are left undecided (only the broken ones are listed), if there is no explicit PASSED / NOT PASSED result, or if the result is PASSED. The reviewer cannot open the repository or search it in this case: a report that says so, or that calls some decisions provisional for that reason, is judged on its content exactly as any other and still passes. Each missing one must also name the skill to load to cover it (for example 'skill: framework-testing'); FAIL if the missing requirements name no skill.
