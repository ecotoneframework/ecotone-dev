PASS if all of these hold. (1) `InProcessMessageChannel::send()` gets no new branch that checks whether the message is a replay (the `ErrorContext::DLQ_MESSAGE_REPLIED` header or any other dead-letter or retry marker), whether an event loop / console / runtime is present, or who the caller is, in order to handle the message in a different way; the same holds for an interceptor or decorator placed on every send to that channel. (2) The replay is given its different treatment where it starts or by composition that belongs to the replay flow: for example the dead letter handler (the code that replays) sends the replayed message to the endpoint (`runOnce()`) or to another target instead of to the channel, or the choice is made when the container is built. (3) The handler is run through the endpoint that already exists (`runOnce()` or an equivalent existing path); the answer does not write a second implementation of invoking the handler, the transaction, the retries or acknowledging. A branch added to the channel that only throws an exception (a refusal, for example refusing a send when no event loop runs) is allowed and does not fail the answer. The existing branch on the delivery delay may stay.

FAIL if the channel, or an interceptor that every message sent to the channel passes, reads the replay header (or detects the console, the missing event loop, or the caller) and then handles the message in place, runs the endpoint, or skips a refusal for it; or if the answer adds a second hand-written way of invoking the handler instead of reusing the endpoint.
